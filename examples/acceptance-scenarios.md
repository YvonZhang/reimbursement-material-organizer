# 行为验收场景

日期：2026-07-23

使用三个互相隔离、无共享对话上下文的代理进行只读推演：一个不读取 Skill 作为基线，两个读取本 Skill 分别执行通用模式和智慧互通预设模式。场景不连接真实邮箱，也不使用真实票据。

## 无 Skill 基线

输入包含：

- 邮箱不可用；
- 同一张 100 CNY 发票的 PDF/XML；
- 同一行程的 80 HKD 收据与 74 CNY 支付截图；
- 一张无法读取的酒店图片；
- 本次任务要求新增“停车费”分类。

基线结果出现两项不符合目标的行为：

- 未确认报销口径就直接计入 74 CNY；
- 没有停车材料仍创建空“停车费”分类。

## 通用模式

读取 Skill 后，同一场景得到：

- 邮箱不可用时继续本地材料模式，并明确报告未搜索邮箱。
- PDF/XML 识别为一组，只计算 `100.00 CNY` 一次。
- 80 HKD 与 74 CNY 未强行选择或相加，标记金额待复核。
- 无法读取的酒店图片保留并列入待复核，不猜测金额。
- 应用本次任务的“停车费”分类规则，但未创建空分类。
- 当前确定合计只有 `100.00 CNY`。
- 输出包含分类清单、`整理摘要.txt`、`检查.txt`，以及需要时创建的 `待复核/待复核清单.txt`。

## 智慧互通预设

输入包含已启用 `hutong` 的档案、可用的企业 163 只读邮箱能力，以及两条本次任务覆盖规则：搜索到行程结束后 7 天、机场巴士归“其它”。

结果得到：

- 明确执行 `本次任务 > 用户档案 > 公司预设 > 通用规则`。
- 邮箱只执行搜索、读取和下载附件，不执行发送、转发、归档、删除或标签修改。
- PDF/XML/OFD 三种格式只形成一个计算项。
- 无确定金额的行程单作为辅助材料或待复核项，不进入确定合计。
- 本地出租车证据不能替代跨城主票据，北京至张家口标记“疑似缺失”。
- 机场巴士按本次任务归“其它”，不使用低优先级默认分类。

## 重复验收

修改 Skill 的规则优先级、邮箱降级、去重、币种或待复核逻辑后，重复以上两个读取 Skill 的场景，并对照每条结果。任何一项偏离都应先修正规则再发布。
